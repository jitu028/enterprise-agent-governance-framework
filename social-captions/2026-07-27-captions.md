## 🔵 LinkedIn Post (Long-form Architecture Focus)

**Headline**: Why standard OAuth fails for Autonomous AI Agents (and how RFC 8693 fixes it) 🤖🔐

When an AI agent executes actions on behalf of a user—querying CRMs, updating databases, or triggering webhooks—how do you guarantee it doesn't overstep user permissions?

Passing raw user access tokens to autonomous subagent chains is a massive security risk. If a subagent is compromised via prompt injection, your user's entire identity is exposed.

Enter **RFC 8693 OAuth 2.0 Token Exchange** for Non-Human Agents (NHA).

Under Pillar 01 of the **Enterprise Agent Governance Framework (EAGF)**:
1️⃣ The human user invokes the agent workflow with a subject token.
2️⃣ The agent exchanges the user token for a **short-lived delegated token (max 15-min TTL)**.
3️⃣ The resulting JWT explicitly embeds an `act` (Actor) claim representing the NHA identity.
4️⃣ Downstream tool gateways verify both *who requested the action* and *which specific agent executed it*.

Check out the full spec and architecture breakdown in our open-source repo! ⬇️
